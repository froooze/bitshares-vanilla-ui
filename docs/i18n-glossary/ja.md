# Japanese glossary — `bitshares-vanilla-ui`

This is the file an external auditor reads **before** trusting a machine-filled
Japanese translation. It fixes **one Japanese term per concept**, so a single
correction here (plus the same word in `vanilla/locales/ja.json`) propagates
everywhere instead of leaving three near-synonyms in the UI.

**How to use it**

- Translate the English term in column 1 as the Japanese term in column 2. Do not
  invent a second Japanese word for the same concept: a synonym split is the one
  mistake this file exists to prevent.
- Column 3 says why, and names the `ja.json` keys that already prove the wording.
  Keys cited there were read out of `vanilla/locales/ja.json` after the
  2026-10-13 chunk-C pass (`tooling/apply_i18n_ja_chunkC.py` filled the last 161
  signing/UX strings; 56 stayed English on purpose and are listed in that
  script's `KEPT_ENGLISH`, and its `--verify` proves the two tables account for
  every key of the file). A citation is evidence, not decoration: in the notes, a
  Japanese WORD in **bold** is a form under discussion, not a locale key — only
  things shaped like `section.key` are citations.
- "N strings" below means: N keys of `ja.json` whose value differs from
  `en.json` and contains the Japanese word, counted on the shipped file
  (3,882 translated keys, 56 byte-identical to English by design). A count is a
  smoke alarm for a synonym split, not a definition.
- Corrections land through the `translation` issue label on the project tracker —
  the same route `#/help/translation-limitations` in the wallet gives readers.
- **Status:** the Japanese column below is the agreed vocabulary, not yet a claim
  of human review. The Japanese fill cross-checked every row against `ja.json` and
  chose the form that file actually uses. Until a person has read a string in
  Japanese, the wallet labels it machine-filled — in the reader's own language
  (`i18n.badge_body`, 「これらの翻訳は機械が書いたもので、人が確認したものではありません。署名画面に * が付いた行は、元の英語も併せて表示されます。」)
  — and every signing line marked `*` shows the English one tap away
  (`i18n.risk_show_english`, 「この行の英語原文を表示」).
- **Every row names the form `ja.json` uses.** Where a second form exists for the
  same concept, the row lists **every** string carrying it — as a counter-example
  (align it on the next pass) or as a same-root other sense (leave it alone). A
  glossary that breaks a dozen correct trading strings is worse than no glossary.
- **Typography.** `ja.json` carries NO ASCII apostrophe, NO typographic
  apostrophe (U+2019), NO ideographic space and NO Cyrillic letter in any value
  this project writes — Japanese needs none of them. The only apostrophes left in
  the file sit inside untranslated English. Japanese does not "fix" an English
  apostrophe in by transliterating it: `vote.proxies_follow_another_account_s_slate_re`
  and `barter.two_sided_atomic_swap_preview_preview_first_t` rephrase the English
  possessive (他のアカウントの / 双方) instead of borrowing it. Japanese quotes a
  button with 「」 (`auth.multisig_step_propose` 「送信 / 提案」,
  `createworker.draft_a_worker_op_34_preview_is_live_review_q` 「署名して送信」,
  `barter.two_sided_atomic_swap_preview_preview_first_t` 「提案」), takes a spaced
  em dash for an aside ( — ) and `…` for a loader. The one space Japanese does use
  is the 和欧間 gap around a Latin or numeric run — "3 ホップ以内", "24 時間",
  "6 ホップのプール経路", "2 つのアセット", "NFT の URI" would have needed one, but
  `asset.nft_uri_field` is byte-identical to English on purpose (see below).
- **The brevity hazard.** Japanese is far more compact than English, and a signing
  dialog shows both lines. Where a short Japanese rendering could drop an amount, a
  direction, an irreversibility or a permission, this file's rows point at the
  fuller form on purpose: `trade.uc_total` is 売却する合計数量 (not 合計),
  `borrow.bids_no_cancel` keeps both 取り消せません and the two outcomes
  (執行されるか、期限切れ), `transfer.enclosed_op_note` keeps 承認がすべてそろってから,
  `instant.preview_balances_note` keeps 残高は確認していません, and
  `vote.retried_prefix` / `vote.retry_self` say 自分自身のアカウント so the reader can
  see whose stake signed.
- **Three disagreements this file had to settle, recorded so a reviewer can check
  them.** (1) `tour.s3_body` first read 深度 for "depth"; the shipped word is
  **デプス** (10 strings before the fix: `market.depth_title`, `pool.depth_title`,
  `market_book.depth_plot`), so the tour was corrected to デプス — a tour is where a
  reader is being taught the vocabulary, and a minority form there is the most
  expensive kind. (2) `xrate.base_pinned` first read 基準列; the shipped base/quote
  pair is ベースアセット / クォートアセット (`credit.ph_base_asset`,
  `credit.ph_quote_asset`), so the column names follow that pair as ベース列 /
  クォート列. (3) The opposite decision: `asset.nft_uri_field` stays **byte-identical
  to English** (`NFT URI`), because `asset.nft_row` beside it is the same Latin
  acronym and chunk-A had already declared the field English; a later batch that
  "improved" it would have turned a green `--verify` red for no reader's benefit.
  Both rewrites are listed in `tooling/apply_i18n_ja_chunkC.py`'s `SUPERSEDED`,
  which is the only value that script is ever allowed to replace.

Placeholders (`%(name)s`), URLs, object ids (`1.2.x`), asset symbols and theme
or network ids are **byte-verbatim** in every language and never appear here.
The 56 keys of `ja.json` that are byte-identical to `en.json` on purpose are
listed in full in `tooling/apply_i18n_ja_chunkC.py`'s `KEPT_ENGLISH`, and fall into
six groups: brands (`shell.brand`, `shell.footer_brand`, `shell.footer_brand_vanilla`),
network/theme ids (`settings.network_mainnet`, `settings.network_testnet`,
`settings.network_devnet`, `settings.theme_original_blue`, `settings.theme_light`,
`settings.theme_dark`), chain acronyms (`htlc.title`, `menu.p_htlc`,
`account_net.class_htlc`, `asset.nft_row`, `asset.nft_uri_field`, `asset.tab_uia`,
`asset.tab_pma`, `asset.mcr_row`, `explorer.th_mssr`, `explorer.feed_mcr_mssr`,
`explorer.id_row`, `misc.id`, `proposal.id`, `ticket.id`, `vesting.id`,
`createworker.url`, `vote.url`, `i18n.badge_chip`), indicator and op acronyms
(`market.ov_sma`, `market.ov_ema`, `market.ov_psar`, `market.ov_bb`, `explorer.op_prefix`,
`explorer.op_badge_prefix`, `explorer.tx_prefix`), the `—` / `…` / `wss://…` sentinels
(`settings.dash`, `settings.pending`, `market.stat_empty`, `assets_feed.s1`,
`explorer_assets.s1`, `settings.custom_placeholder`), template glue
(`explorer.feed_publisher_title`, `explorer.feed_mcr_mssr_title`, `account_net.detail_span`,
`market.map_edge_price`, `market_net.col_spark`, `market_net.edge_card`,
`market_net.edge_card_price`, `pool_net.edge_card`, `pool_net.edge_nobal`,
`pool_net.node_card`, `shell.footer_net_host`) and example payloads the reader
overwrites (`account_net.seeds_placeholder`, `ticket.airdrop_example_ph`,
`viewing.dialog_placeholder`, `xrate.token_placeholder`, `pool.share_or_pool_hint`).

Same root, other sense and correct as they stand — "Viewing as" is the read-only mode, not a kind of account: `proposal.viewing_as` 「%(name)s（%(id)s）として閲覧中 — ご自身として操作するにはアンロックしてください。」, `viewing.notice_locked` (same sentence, byte for byte), `viewing.header_default` 「committee-accountとして閲覧中（ロック中）」. | asset | アセット | Any token on chain (`account.asset_th` 「アセット」, `misc.asset` 「アセット」, `xrate.asset_col` 「アセット」), 290 strings. Never 「資産」 — that is an off-chain asset, and a reader who sees 資産 in a balance row cannot tell a token from a house. Same root, other sense and correct as they stand — the FUND that serves a settlement is a **ファンド**, never アセット: `borrow.check_settlement_fund` 「決済ファンドを確認」, `prediction.settlement_fund` 「決済ファンド」. | balance | 残高 | What an account holds (`account.balance_th` 「残高」, `vesting.balance` 「残高」, `credit.current_balance` 「現在の残高」, `trade.balance` 「残高: 」), 76 strings. Never 「合算」 and never 口座. Same root, other sense and correct as they stand — claiming one is a separate chain action and keeps its own verb **請求** (`account.op_balance_claim` 「残高請求」, `vesting.total_to_claim` 「請求合計」, `wallet.claim_vesting_balances` 「ベスティング残高を請求」), which is the torrent client's word reused deliberately: the chain operation is `balance_claim`. A BLINDED balance is not a different word: `vesting.blinded_balances_read_only` 「プライベート残高（読み取り専用）」 (retired form: ブラインド残高). |
| smartcoin | スマートコイン | A market-pegged asset (`asset.smartcoin_row` 「スマートコイン」, `explorer.no_smartcoins` 「このノードにフィード付きスマートコインがありません。」), 23 strings. Never 「スマートアセット」. Same root, other sense and correct as they stand — the *private-feed* variant and the *prediction-market* variant keep their own words in the same article (`help.topic_assets-private_body` 「連動アセット、私的フィード」, `asset.pma_row` 「予測市場」), and the GLOSS the help prose introduces the concept with is 市場連動アセット (`help.topic_assets-mpa_title` 「市場連動アセット」), which is not a replacement for the term. Its peg is 裏付けアセット (`prediction.backing_asset` 「裏付けアセット」) — see the *collateral* row for why the peg and the stake are two different words. |
| collateral | 担保 | Backing locked behind a smartcoin or a credit position (`borrow.hdr_collateral` 「担保」, `credit.collateral` 「担保」, `account.margin_hint` 「借入ページ（#/borrow）から担保をロックしてください」), 46 strings. Never **抵押** (0 strings — that word appears nowhere in the dictionary) and never the untranslated "collateral". Same root, other sense and correct as they stand — the coin a smartcoin is pegged to is a **裏付けコイン** on the gateway page (`gateway.backing_fact` 「裏付けコイン」) and the asset behind a prediction is 裏付けアセット (`prediction.backing_asset`); *backing* is the peg, *collateral* is the stake posted against a loan, and `borrow.a_bid_locks_your_collateral_against_the_settl` keeps the loan sense. The MARGIN position is マージンポジション (`account.margin_positions` 「マージンポジション」, `borrow.borrow_margin` 「借入（マージン）」), a different object with its own word. |
| precision | 精度 | Decimal places an asset stores (`explorer.precision_row` 「精度」, `explorer.th_precision` 「精度」, `asset.precision_field` 「精度（0–12）」), 18 strings. Never retyped inside an amount string, and never translated away: `eslab.hint_donors` 「期間内のカウント値です。合計は生の整数です — アセットの精度で割ってください。」, `eslab.hint_holders` 「残高は生の整数です — アセット精度で割ってください。」, `eslab.prec_unknown` 「精度不明 — 生の整数。」 Same root, other sense — the *quote* side's precision keeps the same word inside the compound: `explorer_assets.s2` 「利用不可（クォート精度不明）」, `explorer.unavailable_quote` 「利用不可 (クォート精度不明)」. |
| share | シェア | A pool share: `pool.shares_field` 「LP シェア」, `pool.stake_shares_row` 「推定 LP シェア」, `pool.share_asset_field` 「シェアアセット」, `help.topic_pools_text` 「プールシェアをステークできます。」, `pool.list_sub` 「ステークは LP シェアに対する両脚の預け入れです。」, 12 strings for the word. The narrowed form **LP シェア** is the pool token's own unit and is correct where it stands; the plain シェア in the same sense is the same concept shortened, not a different term. Never **株式** and never **持分** in this sense — see the two rows below. Same root, other sense and correct as they stand — a PREDICTION market's stake is 持分, a different object with its own word. |
| pool share | LP シェア | What you hold in a liquidity pool (`pool.shares_field` 「LP シェア」, `pool.stake_shares_row` 「推定 LP シェア」, `pool.list_sub`). The plain **シェア** in the same sense is the same concept shortened. A pool share is NOT the stake you deposit (next row) and NOT a シェアアセット (`pool.share_help`), which is the token, not your fraction of it. |
| stake | ステーク | The locked balance that earns voting weight or a pool's yield (`pool.list_sub` 「ステークは LP シェアに対する両脚の預け入れです。」, `menu.d_tickets` 「投票ロックされたステークと増加する重み。」, `help.topic_tickets_body` 「ステークをロック、重みを育てる」), 63 strings (31 pool/vote strings plus 32 voting-stake strings, which carry ステーク inside 投票ステーク). Never 「质押」 (that is a Chinese character — see the typography note) and never 「賭け」. The column header keeps the pair `pool.stake_unstake_col` 「ステーク/解除」. `vote.ballot_intro` 「あなたのステークがウィットネスと委員会を選び、ワーカーを支えます」 and `vote.proxy_follows` 「 — あなたのステークはこのアカウントに従います。」 both say ステーク, so the voting desk and the pool desk agree. A pool share is not a シェア, and one side of a swap is not a **脚** (`barter.no_legs` 「レッグなし」, `xrate.unpriced` 「この経路のいずれかの脚に、まだ記録されたスワップがありません。」). |
| liquidity pool | 流動性プール | A CPMM market (`pools.title` 「流動性プール」, `pool_detail.title` 「流動性プール」, `help.topic_pools_title` 「流動性プール」), 12 strings for the full form and 124 for **プール** — the same word shortened, which is what the tables, the buttons and the pool network use (`pool_net.title` 「プールネットワーク」, `pool_net.col_pool` 「プール」, `nav.pools` 「プール」, `pools.selector_title` 「プールセレクター」, `txbuilder.link_pools` 「プール」). | exchange | 取引所 | The DEX venue — and the word is UNANIMOUS where English says "Exchange", which is worth recording because the same master renders 取引所 in the market page, the book page and the desk: `market.title` 「取引所」, `market_book.title` 「取引所」, `trade.title` 「取引所」, `nav.exchange` 「取引所」, `menu.p_exchange` 「取引所」, `market.exchange_desk` 「取引所デスク」, 33 strings. Same root, other sense and correct as they stand — 板取引 inside `help.topic_bitshares_body` names the same venue under its older Japanese name and is a variant, not a split. **Never 取引 for the venue**: 取引 is already owned by the op-label table and `trade.chain_hint` for a *transaction*, which is why this row and the *transaction* row must both be read. |
| desk | デスク | The page a flow lives on (`market.exchange_desk` 「取引所デスク」, `instant.open_the_full_desk` 「フルデスクを開く」, `menu.d_exchange` 「オーダーブック、チャート、売買デスク。」, `tour.away_note` 「取引所デスクのページです — 開くと、この場所が強調表示されました。」), 22 strings. Never 「机」 in UI chrome. | swap | スワップ | A pool exchange (`account.op_pool_swap` 「プールスワップ」, `pool.swap_desk` 「スワップデスク」, `account.sum_pool_swap` 「プール %(pool)s で %(sell)s → 少なくとも %(buy)s にスワップしました」, `pool_detail.candle_count` 「%(swaps)s スワップ」, `xrate.status` 「%(total)s プール中 %(done)s 件が直近のスワップを保持」), 41 strings. | limit order | 指値注文 | A resting priced order (`account.op_limit_create` 「指値注文作成」, `account.op_limit_cancel` 「指値注文取消」, `help.topic_dex-trading_text` 「正確な価格での指値注文。インスタント取引は同じ経路を1画面にまとめたものです。」, `proposal.op_1` 「指値注文作成」), 11 strings. Same root, other sense and correct as they stand — the order-type tabs `trade.tab_single` 「単一」 / `trade.tab_scaled` 「スケール」 are not limit orders, and neither is `debit.uc_order` 「注文」 on the unlock dialog. |
| order | 注文 | Anything resting on or filled from the book (`market.col_order` 「注文」, `instant.order_prefix` 「注文: 」, `trade.uc_orders` 「注文」, `trade.co_orderid` 「注文ID」), 115 strings.
