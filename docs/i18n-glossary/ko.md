# Korean glossary — `bitshares-vanilla-ui`

This is the file an external auditor reads **before** trusting a machine-filled
Korean translation. It fixes **one Korean term per concept**, so a single
correction here (plus the same word in `vanilla/locales/ko.json`) propagates
everywhere instead of leaving three near-synonyms in the UI.

**How to use it**

- Translate the English term in column 1 as the Korean term in column 2. Do not
  invent a second Korean word for the same concept: a synonym split is the one
  mistake this file exists to prevent.
- Column 3 says why, and names the `ko.json` keys that already prove the wording.
  Keys cited there were read out of the shipped `vanilla/locales/ko.json`. A
  citation is evidence, not decoration: in the notes, a Korean WORD in **bold**
  is a form under discussion, not a locale key — only things shaped like
  `section.key` are citations.
- "N strings" means: N keys of `ko.json` whose value differs from `en.json` and
  contains the Korean word, counted on the shipped file. A count is a smoke
  alarm for a synonym split, not a definition.
- Corrections land through the `translation` issue label on the project tracker —
  the same route `#/help/translation-limitations` the wallet gives readers
  (`help.topic_translation-limitations_title` "번역의 한계").
- **Status:** the Korean column below is the agreed vocabulary, not yet a claim
  of human review. Until a person has read a string in Korean, the wallet labels
  it machine-filled (`i18n.badge_body` "이 번역은 기계가 쓴 것이며 사람이 확인하지
  않았습니다.") and every signing line marked `*` shows the English one tap away
  (`i18n.risk_show_english` "이 줄의 영어 원문 보기").
- **Every row names the form `ko.json` uses.** Where a second form exists for the
  same concept, the row lists **every** string carrying it — as a counter-example
  (align it on the next pass) or as a same-root other sense (leave it alone). A
  glossary that breaks a dozen correct voting strings is worse than no glossary.
  Every count and every key below is machine-verified against the shipped
  dictionary by `tooling/i18n-glossary-multi-test.js`.
- **Register and punctuation.** `ko.json` is a polite split register: statements
  end in ~습니다, step-by-step instructions in ~십시오, and bare nouns carry UI
  labels. Particle slots are written as the dual form `…은(는)`, `…을(를)` and
  `…(으)로` (5 keys each) so one string serves every placeholder, and compound
  facts are glued with the middle dot `·` (`account_net.detail_line`,
  `account_net.twin_count`). Do not "tidy" a dual particle into a single
  one, and do not insert spaces around `·`.
- **Loanwords stay Korean.** `swap` and `proxy` are **not** left in Latin here:
  the dictionary writes 스왑 and 프록시 and contains zero Latin occurrences of
  either word. HTLC alone stays Latin, as in every other locale.

Placeholders (`%(name)s`), URLs, object ids (`1.2.x`), asset symbols and theme
or network ids are **byte-verbatim** in every language and never appear here.
