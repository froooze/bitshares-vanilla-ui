# Russian glossary — `bitshares-vanilla-ui`

This is the file an external auditor reads **before** trusting a machine-filled
Russian translation. It fixes **one Russian term per concept**, so a single
correction here (plus the same word in `vanilla/locales/ru.json`) propagates
everywhere instead of leaving three near-synonyms in the UI.

**How to use it**

- Translate the English term in column 1 as the Russian term in column 2. Do not
  invent a second Russian word for the same concept: a synonym split is the one
  mistake this file exists to prevent.
- Column 3 says why, and names the `ru.json` keys that already prove the
  wording. Keys cited there were read out of `vanilla/locales/ru.json` after the
  2026-10-13 chunk-C pass (`tooling/apply_i18n_ru_chunkC.py` filled the last 166
  signing/UX strings; 45 more stayed English on purpose and are listed in that
  script's `KEPT_ENGLISH`). A citation is evidence, not decoration: in the notes,
  a Russian WORD in **bold** is a form under discussion, not a locale key — only
  things shaped like `section.key` are citations.
- "N strings" below means: N keys of `ru.json` whose value differs from
  `en.json` and contains the Russian word, counted case-insensitively on the
  shipped file. A count is a smoke alarm for a synonym split, not a definition.
- Corrections land through the `translation` issue label on the project tracker —
  the same route `#/help/translation-limitations` in the wallet gives readers.
- **Status:** the Russian column below is the agreed vocabulary, not yet a claim
  of human review. The Russian fill cross-checked every row against `ru.json` and
  chose the form that file actually uses. Until a person has read a string in
  Russian, the wallet labels it machine-filled — in the reader's own language
  (`i18n.badge_body`, «Эти переводы написаны машиной и не проверены человеком.») —
  and every signing line marked `*` shows the English one tap away
  (`i18n.risk_show_english`, «Показать английский оригинал строки»).
- **Every row names the form `ru.json` uses.** Where a second form exists for the
  same concept, the row lists **every** string carrying it — as a counter-example
  (align it on the next pass) or as a same-root other sense (leave it alone). A
  glossary that breaks a dozen correct voting strings is worse than no glossary.
- **Typography.** `ru.json` carries NO ASCII apostrophe and NO typographic
  apostrophe (U+2019) in any translated value — Russian quotes with «...», and
  that rule is enforced file-wide by gate G7 of all three Russian scripts. The
  only apostrophes left in the file sit inside untranslated English. Do not
  "fix" one into the other.

Placeholders (`%(name)s`), URLs, object ids (`1.2.x`), asset symbols and theme
or network ids are **byte-verbatim** in every language and never appear here.
