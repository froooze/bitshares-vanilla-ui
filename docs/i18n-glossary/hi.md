# Hindi glossary — `bitshares-vanilla-ui`

This is the file an external auditor reads **before** trusting a machine-filled
Hindi translation. It fixes **one Hindi term per concept**, so a single
correction here (plus the same word in `vanilla/locales/hi.json`) propagates
everywhere instead of leaving three near-synonyms in the UI.

**How to use it**

- Translate the English term in column 1 as the Hindi term in column 2. Do not
  invent a second Hindi word for the same concept: a synonym split is the one
  mistake this file exists to prevent.
- Column 3 says why, and names the `hi.json` keys that already prove the wording.
  Keys cited there were read out of the shipped `vanilla/locales/hi.json`. A
  citation is evidence, not decoration: in the notes, a Hindi WORD in **bold**
  is a form under discussion, not a locale key — only things shaped like
  `section.key` are citations.
- "N strings" means: N keys of `hi.json` whose value differs from `en.json` and
  contains the Hindi word, counted on the shipped file. A count is a smoke alarm
  for a synonym split, not a definition.
- Corrections land through the `translation` issue label on the project tracker —
  the same route `#/help/translation-limitations` the wallet gives readers
  (`help.topic_translation-limitations_title` "अनुवाद सीमाएँ").
- **Status:** the Hindi column below is the agreed vocabulary, not yet a claim of
  human review. Until a person has read a string in Hindi, the wallet labels it
  machine-filled (`i18n.badge_body` "ये अनुवाद एक मशीन ने लिखे हैं और किसी मानव ने
  जाँच नहीं की।") and every signing line marked `*` shows the English one tap away
  (`i18n.risk_show_english` "इस पंक्ति का अंग्रेज़ी संदर्भ दिखाएँ").
- **Every row names the form `hi.json` uses.** Where a second form exists for the
  same concept, the row lists **every** string carrying it — as a counter-example
  (align it on the next pass) or as a same-root other sense (leave it alone). A
  glossary that breaks a dozen correct voting strings is worse than no glossary.
  Every count and every key below is machine-verified against the shipped
  dictionary by `tooling/i18n-glossary-multi-test.js`.
- **Register.** `hi.json` is a formal, second-person-plural register: the reader
  is **आप** (`about.hero_lede` "आपकी कुंजियाँ यह ब्राउज़र कभी नहीं छोड़तीं।"), and
  instructions use the polite imperative. Keep the nukta where the file writes it:
  फ़ (फ़ीड, रेफ़रल, ऑफ़र), ज़ (अनुवाद, ब्राउज़र), ड़ (ऑफ़र) — do not "normalise" a
  नुक़्ता away, and do not add one where the file omits it.
- **Loanwords stay transliterated.** `swap` and `proxy` are **not** left in Latin
  here: the dictionary writes स्वैप and प्रॉक्सी and contains zero Latin
  occurrences of either word. HTLC alone stays Latin, as in every other locale.

Placeholders (`%(name)s`), URLs, object ids (`1.2.x`), asset symbols and theme
or network ids are **byte-verbatim** in every language and never appear here.
